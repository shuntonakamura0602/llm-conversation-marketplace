# dialogue — LLM Conversation Marketplace MVP

人間とAIの対話を読み物として公開・発見する、日本語向けのMVPです。検証するのは「ひとつ読んだ人が、もうひとつ読み、後日戻ってくるか」。課金、ランキング、フォロー、コメント、AIによる要約は実装していません。

## ローカル起動

Node.js 22.13以降（開発時は24）を使用します。

```sh
npm ci
cp .env.example .env.local
npm run dev
```

http://localhost:3000 を開きます。Supabase未設定なら、20件の架空の編集サンプルを閲覧できます。実在する人とAIの会話ではありません。ログイン・投稿・イベント保存・報告送信は接続設定後に有効になります。接続済みデータベースが空の場合は空の一覧を表示し、サンプルと実データは混在させません。

## 環境変数

| 変数                            | 内容                                        |
| ------------------------------- | ------------------------------------------- |
| `NEXT_PUBLIC_SUPABASE_URL`      | SupabaseプロジェクトのURL                   |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabaseのanonキー（またはpublishableキー） |

サービスロールキーは使用しません。公開キーでアクセスし、RLSで権限を検証します。`.env.local`はGitに含めません。

## Supabase設定

1. Supabaseプロジェクトを新規作成し、SQL Editorで `supabase/schema.sql` を一度実行します。既存テーブルのあるDBにはそのまま実行しないでください。
2. Authentication → ProvidersでGoogleを有効にし、Google Cloudで作成したOAuthクライアントID・シークレットを設定します。Google側の承認済みリダイレクトURIはSupabaseに表示される `https://PROJECT.supabase.co/auth/v1/callback` です。
3. Authentication → URL ConfigurationでSite URLを本番URLに設定し、Redirect URLsに `http://localhost:3000/auth/callback` と本番の `https://YOUR_DOMAIN/auth/callback` を追加します。プレビュー環境を利用する場合はそのURLも登録してください。
4. `.env.local`に上記2変数を入れ、開発サーバーを再起動します。
5. Googleでログインします。DBトリガーにより匿名の表示名と一意のユーザー名が作成されます。Googleの本名・プロフィール画像を自動公開しません。投稿ページから自分のプロフィールへ移動し、表示名・自己紹介・属性を編集できます。

認証トリガーは新規ユーザー作成時に動作します。既存AuthユーザーがいるDBを利用する場合、運営者がそのIDに対応する `public.users` 行を作成してください。

## 実装範囲

- `/`: 新着の公開会話、タグ絞り込み、簡易キーワード検索、追加表示。最初の100件を取得します。
- `/conversations/[id]`: 概要、ユーザーとAIを区別した全文、同じタグの会話、著者の会話、フィードバック、30円の支払意向調査、問題報告。
- `/users/[username]`: 匿名プロフィールと公開会話。本人にはプロフィール編集と非公開会話一覧も表示します。会話詳細から公開・非公開を切り替えられます。
- `/submit`: 認証必須。ChatGPT共有URLからの取り込み、貼り付け本文の解析・プレビュー、論点、タグ、公開/非公開設定、確認事項への同意、サーバー側検証を備えます。
- `/login`, `/auth/callback`: Google OAuth（PKCE）とCookieセッション。`proxy.ts`でセッションを更新します。

### 会話の入力

ラベルは独立した行に書きます。先頭はUSER、以降は交互にします。空の本文や不正な順番はエラーになります。メッセージ数を表示し、600文字/分で読了時間を計算します。「turn」の曖昧さを避け、UIではメッセージ数と表記しています。

```text
USER:
AI時代に、会社員でいる意味は変わりますか？

ASSISTANT:
作業と、組織が担う役割を分けて考えてみましょう。
```

本文はHTMLとして実行せず、改行を維持したプレーンテキストとして表示します。Markdownのリッチレンダリングは対象外です。ChatGPTの共有URLからの取り込みは次の手順で利用できます。

## 共有URLから投稿する

Supabase・Googleログインの設定後、すべてのログインユーザーが利用できます。Supabaseの運営アカウントを投稿者ごとに作る必要はありません。

1. サイトにGoogleでログインし、「会話を投稿」を開きます。
2. `https://chatgpt.com/share/…` のURLを貼り、「会話を取り込む」を押します。
3. タイトル、メッセージ数、文字数と全文を確認し、「この会話をフォームに反映」を押します。
4. タイトル・使用LLM・全文が自動入力され、説明には最初の質問が仮入力されます。必要なら編集し、タグや主な論点を追加します。本文を手作業で整形する必要はありません。
5. 公開設定と権利・個人情報の確認を済ませ、「会話を保存する」を押します。公開した会話は一覧に表示されます。

取り込みだけではDBへの保存・公開は行いません。取り込んだ本文は要約せず保持し、未編集の本文は構造化データで保存するため、引用内の `USER:` なども会話の区切りと混同しません。本文を手動編集すると通常の貼り付けパーサーへ切り替わります。取り込みによってフォームのタイトル・説明・LLM・本文が置き換わる旨を反映前に表示します。

### 対応と制約

- ChatGPTの公開共有リンクに対応。旧 `chat.openai.com/share/…` は現在のドメインへ正規化します。Claude等のURLや通常のプライベート会話URLは未対応です。
- サーバーが共有ページの埋め込みデータを読み取ります。公式の取り込みAPIではなく、ChatGPT側の形式変更・アクセス制限で取得できなくなる場合があります。その場合は理由を表示し、従来の本文貼り付けを利用できます。
- ユーザーとAIの表示対象のテキストのみを取得し、内部情報、システムメッセージ、ツール結果、非表示メッセージは投稿本文に含めません。分岐は選択中の経路だけを取得します。
- 画像・音声・添付ファイルは保存しません。含まれる場合は警告と本文中の印を表示します。自動要約や抜粋はしません。
- 本文10万文字、取得HTML 8MiB、取得15秒の上限。上限超過や不正な話者順では、省略せずエラーにします。
- `/api/import` はログイン必須。URLのHTTPS・ホスト・パスを限定し、任意URLやリダイレクト先を取得しません。共有ページのJavaScriptは実行しません。レスポンス・取得結果をキャッシュしません。
- 1ユーザー10回/分、同時取得3件のプロセス単位の簡易制限があります。複数インスタンス全体で共有されるレート制限ではありません。
- Supabase未設定の間は投稿・URL取り込みを有効にしません。下書きの一括取り込みや自動公開はありません。

## データとアクセス制御

`users`、`conversations`、`events`、`reports`を作成します。会話の本文は `Message[]` のJSONB、タグと論点はtext配列です。

- 公開会話とプロフィールは誰でも閲覧可能。
- 非公開会話は本人だけ閲覧可能。検索・関連会話・他人のプロフィール一覧には出ません。
- 投稿は本人のIDのみ許可。表示回数をユーザーが直接更新する権限はありません。
- events/reportsは訪問者から直接の読取り・書込みを禁止。検証付きRPCだけが記録します。イベントのuser_idはDB側のauth.uid()から取得します。
- ログと通報の確認は管理者がSupabase SQL Editorで行います。公開ダッシュボードはありません。
- 公開中の会話のみ計測対象。表示回数は会話×セッションで重複を除外します。

## Analytics

外部の計測SDKは追加せず、Supabase `events` に仕様書のイベントを保存します。運営者は `supabase/analytics.sql` をSQL Editorで実行して集計できます。

`page_view`, `conversation_card_click`, `conversation_view`, `conversation_read_25/50/75/100`, `related_conversation_click`, `author_profile_click`, `feedback_click` を記録します。フィードバックの種類と支払意向は `metadata.feedback` に入ります。匿名IDをlocalStorage、セッションIDをsessionStorageに保存し、30分の無操作で新しいセッションにします。ストレージ拒否時は計測をスキップし、閲覧を優先します。個々のイベントはベストエフォート送信で、オフライン再送キューはありません。

読了率は本文の累積文字数25/50/75/100%に置いたマーカーが画面に入った割合です。厳密な読書時間や理解度を表すものではなく、短い会話では複数マーカーが同時に見える場合があります。主指標は「会話閲覧セッションのうち、異なる会話を2件以上閲覧した割合」。平均最大読了率、会話数/セッション、別日再訪、反応率も集計できます。カード単位のインプレッションを測っていないため、一覧からのクリック率はホーム閲覧セッションに対する近似指標です。

匿名IDあたりのイベント量と会話あたりの報告量には簡易制限があります。匿名IDは訪問者が変更できるため、本格的なbot対策ではありません。SQLのイベント重複排除は同じセッション内の再訪を1回と数えます。運営者の試験アクセスや同一人物の複数端末は分析時に考慮してください。

## モデレーション

投稿者に個人情報・秘密情報・転載について確認を求めます。詳細ページから理由と任意の詳細を報告できます。運営者はSQL Editorで未対応報告を確認し、対象会話の `published=false` への変更、または削除で対応します。報告テーブルのstatusを `resolved` / `dismissed` に変更できます。サンプルモードでは報告・反応は保存されません。

## 初期コンテンツ

`lib/samples.ts` に架空の編集例20件を用意しています。実サービス公開前に開発者自身の権利確認済みの会話を最低20件、ログインして投稿してください。サンプルは本物の利用者の会話と誤認されないよう、DBへ自動投入しません。

## Vercelへのデプロイ

1. このリポジトリをGitHubへpushし、VercelでImportします。Framework PresetはNext.jsを選びます。
2. Production（必要ならPreviewも）に上記2つの環境変数を設定します。
3. Build Commandを `npm run build` にしてデプロイします。
4. 本番URLをSupabaseのSite URL/Redirect URLsへ登録します。
5. 未ログインで一覧→詳細→関連→著者ページ、Googleログイン→投稿→一覧掲載、非公開会話の別ブラウザでのアクセス拒否、Supabaseでイベント記録を確認します。

このリポジトリから自動的にSupabaseプロジェクト作成・Googleの資格情報登録・本番公開は行いません。

### 無料・有料の区切り（β版）

既存プロジェクトは Supabase の SQL Editor で新しいクエリを開き、
`supabase/migrations/20260913_paywall.sql` の内容を貼り付けて Run してください。
新規セットアップは `schema.sql` の実行後にこの SQL も実行します。
既存投稿は、そのまま全文無料で維持されます。

- 新規投稿：本文を入力・取り込み後、「無料で読める範囲」を選択。
- 投稿済み：自分の会話を開き、「無料・有料の区切りを編集」で保存。
- 最初の2メッセージ以上を無料にでき、後から全文無料にも戻せます。
- 有料部分は別テーブルに保存され、投稿者のみ取得できます。公開APIには無料部分のみ返します。
- タイトル・説明・論点は公開情報です。有料本文の内容を転載しないよう編集してください。
- β版のため決済・購入後の閲覧権限は未実装です。30円で読む購入希望を記録しますが、料金は発生しません。

### 投稿の削除とMarkdown表示

ログイン中の投稿者は、会話詳細の「この会話を削除」から確認後に自分の投稿を削除できます。有料部分も削除されます。既存の所有者限定DELETEポリシーと外部キーのCASCADEを使用するため、追加SQLは不要です。

会話本文と投稿プレビューはMarkdown（太字、見出し、リスト、引用、リンク、コード、GFMの表など）に対応しています。既存の本文も表示時に変換されます。HTMLは実行せず、画像はリンクで表示します。読了率の目印はMarkdownを壊さないよう、各割合を含む段落・コードブロックなどの末尾に配置します。
